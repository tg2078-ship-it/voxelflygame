# VOXEL AIRRUN 6.0 — Flight Adventure

6.0은 비행 중 선택과 연속 행동에 목표·점수·평가를 연결하고, 첫 항로부터 도전이 이어지도록 절차 생성과 화면·풍경을 개편한 버전입니다. 5.0.2의 안정성 수정 위에 구현했습니다. 원본 사이트의 HTTP 401 응답으로 원격 소스는 확인할 수 없었으며, 사용자가 Google Drive로 제공한 5.0.1 소스 ZIP을 기준으로 작업했습니다. 외부 사이트에 게시한 상태는 아닙니다.

## 실제 비행 행동으로 진행되는 작전

`FlightAdventure`가 전방 통과 경로·링·코인의 가용성을 확인해 비행 중 작전을 선택합니다. 완료·시간 만료 후 다음 작전으로 이어지며, 같은 수집물이나 경로의 중복 이벤트는 반복 가산하지 않습니다.

| 작전 | 완료 행동 |
|---|---|
| 항로 개척 / PATHFINDER | 표시된 통과 경로 연결 |
| 링 러너 / RING RUNNER | 링 통과 |
| 정밀 비행 / DEAD CENTRE | 링 또는 통과 경로의 중심 통과 |
| 로우 라이더 / LOW LINE | 지면 위 5–12m에서 거리 확보 |
| 블루 스트릭 / BLUE STREAK | 직접 조종하며 가속 거리 확보 |
| 골든 루트 / GOLDEN ROUTE | 코인 수집 |
| 리스크 메이커 / RISK MAKER | 근접 또는 좁은 경로 통과 |
| 클린 윙 / CLEAN WINGS | 피격 없이 연속 통과 경로 완주 |

통과·링·근접·협문과 저공 행동으로 플로우를 쌓습니다. 단계별 배율은 1.00× / 1.15× / 1.30× / 1.50×이며, 유효 행동이 끊기면 감소합니다. 피격 시 플로우가 초기화되고 클린 윙의 진행도도 초기화됩니다. 중심을 통과하면 정밀 보너스를 받습니다. 이 보너스들은 표시용 수치에 그치지 않고 시뮬레이션의 실제 보너스·총점·정산에 반영됩니다.

E 연출 중에는 작전 시계를 멈추고 플로우를 초기화합니다. 자동 연출의 이동으로 직접 조종 작전을 진행시키지 않습니다. 비행 종료 화면은 작전 완수, 정밀 통과, 최고 연속 기록, 보너스 합계와 BRONZE / SILVER / GOLD / ACE 평가를 보여줍니다. 평가는 비행 시간·작전·정밀 통과·연속 행동·무피격 거리로 계산하며, 최고 등급에는 별도의 시간·작전 완료 조건이 있습니다.

## 첫 구간부터 생성되는 항로와 난이도

첫 구간부터 테마별 행동 문법으로 세 가지 행동을 조합합니다. 좌우 회피와 고도 판단을 연결하고 방향·높이·간격을 시드로 생성합니다. 기존 고정 패턴 목록에서 하나를 뽑는 방식 대신 생성한 형상을 통과 가능성 검사에 넣고, 해당 기체가 통과하지 못하면 다른 생성 시도로 재검사합니다.

| 난이도 | 기체 속도 배율 | 기본 행동 간격 | 성격 |
|---|---:|---:|---|
| 여유 / RELAXED | 0.88× | 242m | 넓은 반응 여유와 완만한 고도 변화 |
| 표준 / STANDARD | 1.00× | 210m | 좌우·상하 판단을 연결하는 기본 도전 |
| 숙련 / EXPERT | 1.12× | 182m | 짧은 판단 간격과 큰 경로 변화 |

표의 간격은 생성 기준값입니다. 실제 간격에는 시드별 변화와 진행 강도가 적용됩니다. 속도가 크게 올라가면 기체 조종 성능에 맞춰 지형의 간격을 늘려 판단·회피 시간을 확보합니다. 속도 배율은 기체 성능에 적용되며 고정된 km/h를 뜻하지 않습니다. 여유에서도 충돌과 보상은 유지합니다. 설정 변경은 다음 출격부터 반영됩니다.

## 오늘의 항로와 저장 기록

오늘의 항로는 `America/New_York`의 날짜로 고정 시드를 만듭니다. 날짜 경계는 뉴욕 자정이며 서머타임을 고려해 다음 갱신 시각을 계산합니다. 무한 항로의 무작위 시드와 구분하고, 오늘의 항로 난이도는 표준으로 고정합니다.

일반 비행과 E 사용 비행의 최고 기록을 구분하고, 거리 우선·동거리일 때 점수로 비교합니다. 시도 횟수와 기체·점수·콤보를 기기의 저장 데이터에 남기며 최근 31개 날짜를 보존합니다. 백업 검사와 기존 저장 호환 경로에도 해당 필드를 반영했습니다. 온라인 서버 순위표나 기기 간 자동 동기화를 추가한 것은 아닙니다.

## 화면·공항·풍경

- 격납고를 출격·기체 선택·비행 기록·오늘의 항로를 확인하는 대시보드로 개편하고, 비행 HUD에 작전 진행·플로우·기체 상태·항로 정보를 배치했습니다.
- 로딩·조종사 카드·보상 화면과 비행 평가 화면의 시각 구성을 맞췄습니다. 공항 바닥과 활주로·격납고 구도를 정비했습니다.
- 각 테마의 건물·작업 시설·지형 장식을 구역별 조합으로 구성했습니다. 서로 관련 있는 모델이 함께 나오도록 선택 범위를 정리하고, 해안 섬·절벽과 전경·중경·원경의 식생·암석 배치를 조정했습니다.
- 하늘 그라데이션·수평선·구름 음영과 수면 셰이더를 수정해 해안·날씨·일출과 노을의 색이 이어지도록 했습니다.

Edition12 원본 403종과 모델·텍스처·동작·충돌 자료는 유지합니다. 화면 개편을 위해 원본 자산 파일을 덮어쓰거나 단순 대체 모델로 바꾸지 않았습니다. 배포 시 일부 환경 모델의 근거리 최고 단계를 LOD1으로 선택하는 기존 전달 정책은 별도로 유지합니다.

## 초기 로딩의 변경과 측정 해석

첫 비행에 테마 전체 모델을 미리 요구하던 목록을 줄이고, 시작 구역에 필요한 기본 모델과 실제 생성된 경로의 모델을 준비합니다. 가까운 충돌 모델은 우선 처리하고, 다음 테마는 백그라운드에서 준비합니다. 모델 원본의 상세도를 낮춰 얻은 절감으로 설명하지 않습니다.

대표 해안 덱 프로필에서 기본 모델 목록은 77종에서 21종으로 줄었고, 해당 프로필의 자산 바이트는 약 17.129MB에서 8.915MB로 약 48% 감소했습니다. 이는 같은 프로필끼리의 목록·바이트 비교입니다. 실제 출발 때는 시드로 생성된 경로, 기체, 품질과 캐시에 따라 추가 모델·충돌 자료가 달라지므로 모든 실행의 요청 수·전송량이나 로딩 시간 감소율로 일반화할 수 없습니다.

## 유지한 안정성 수정

5.0.2의 불연속 재질 그룹 병합, 숨긴 부모/미리보기 바닥 처리, 영구 다운로드 실패의 재시도 제한, 품질 전환 시 그림자 셰이더 준비, WebGL 수명 관리, 포커스 상실 후 입력 해제, 프레임 시간 기준 비행 효과, IndexedDB 장애 후 복구 저장과 중복 정산 방어를 유지합니다. 세부 수정의 출처와 당시 검사 결과는 [RELEASE-5.0.2.md](RELEASE-5.0.2.md)에 있습니다.

## 실행과 검증 범위

Node.js 22.13 이상, pnpm 11.25.0을 사용합니다. 프로젝트 루트에서 실행합니다.

```sh
npx --yes pnpm@11.25.0 install --frozen-lockfile
npm run dev
```

검사와 배포용 빌드 명령:

```sh
npm run typecheck
npm run lint:game
npm run test:game
npm run build
```

최종 TypeScript 검사, 게임 ESLint 검사, 배포용 빌드가 통과했습니다. 게임 회귀 러너 38개 묶음 전체 실행과 추가 E 복귀 회귀 1개가 각각 통과했습니다. 현재 `npm run test:game`에는 이 39개 묶음이 모두 등록되어 있습니다.

- 절차 문법 23,493개 검사: 13개 테마·한국 4변형·세 난이도, 첫 해안 32개 시드에서 서로 다른 행동 조합 32개.
- 난이도·저장·시작 경로 91,383개 검사: 22기체 × 3난이도 × 3시드의 198개 시작 구간과 실제 원본 충돌 자료.
- 66개 조종 시뮬레이션 모두 240초 생존. 100개 무조작 시드는 모두 45초 이내 실패하여 직접 회피가 필요함을 확인.
- E: 기본 352개 조합, 고속 조건 216개, 여유·숙련 96개 조합과 이전 실패 형상의 900프레임 재현 검사. 불가능한 고속 시작 36개는 사용권 차감 없이 안전하게 거부.
- 8개 속도 조건에서 각각 30분 분량의 CPU 스트리밍 검사. 이는 실제 30분 GPU 플레이와 구분합니다.
- 403종 원본의 모든 시각 LOD·동작·충돌 자료, 모델 병합·워커·상주 수명, 저장·보상·중복 정산과 품질 전환 회귀를 포함합니다.

6.0의 검증 대상은 작전·보너스·정산, 날짜 경계·일일 기록·저장 호환, 절차 생성·난이도와 기존 게임 회귀입니다. 실제 Chromium에서는 키보드 조종으로 첫 작전을 완료하고 부스트·일시정지·비행 결과·오늘의 항로 기록 저장을 확인했습니다. HIGH↔BALANCED 품질 전환도 반복했습니다. 해당 실행에서 JavaScript·WebGL·HTTP 오류는 관찰되지 않았습니다. 새 저장의 호출명 검증·승인·공항 입장·새로고침 후 복구도 확인했습니다. 390×844와 844×390의 메뉴·난이도·기체 필터·정비·설정을 실제 브라우저에서 검사했습니다. 반응형 기능 검사 일부는 소프트웨어 GPU 입력 지연 때문에 DOM 클릭 이벤트를 사용했으며, 실제 기기의 터치 반응성 검증과 구분합니다. 낮·노을·폭풍·밤의 하늘·구름·수면·지형은 별도의 WebGL 장면에서 셰이더 오류 0건을 확인했습니다.

구조화된 최종 결과와 소스 해시는 [VALIDATION-6.0.json](VALIDATION-6.0.json)에 있습니다. 모바일 강화 버튼의 고정 출격 버튼 가림을 보완한 뒤, 실제 브라우저의 포인터 도달 여부와 강화 적용도 확인했습니다.

브라우저 실행은 소프트웨어 GPU 환경입니다. 실제 PC·모바일 GPU의 FPS·발열·장시간 플레이나 사람 대상 재미 평가는 수행하지 않았습니다. 자동 검사·빌드·화면 관찰을 전체 코드의 완전 검증이나 모든 오류가 없다는 보장으로 확대하지 않습니다. 게시 또는 새 배포 환경 검증도 별도 단계입니다.

5.0 문서의 미리보기 연결 실패는 5.0 당시의 제한입니다. 이후 5.0.2와 이번 6.0의 브라우저 관찰 결과와 구분합니다.
