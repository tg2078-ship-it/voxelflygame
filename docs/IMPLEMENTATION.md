## 인게임 배치

기존 168개 항로 패턴과 테마별 건물 구획에 전체 모델 덱을 추가했습니다. 매 encounter에 최대 10종을 추가하며, 한 덱의 모든 모델을 사용한 뒤 다시 순환합니다. 반복 부속 구획은 새 모델을 위해 교체할 수 있지만 필수 항로와 다른 새 모델의 예약 범위는 보존합니다. 움직임의 전체 보수 경계도 예약합니다. 수선·지면·부두에 맞게 배치하고 모델의 기본 배율은 균일하게 유지합니다.

8개 기본 테마 × 2시드 × 2기체 폭의 32가지 연속 생성 사례에서 덱 전부를 실제 placement로 생성했습니다. 4~8 encounter 안에 각 덱의 모든 모델을 사용했고, 추가 모델의 전체 물리 동작 경계가 필수 통과선과 겹치지 않았습니다. 이는 생성 데이터 검증이며 모든 시드의 GPU 화면을 확인한 기록은 아닙니다.

접근하고 로드된 모델은 비행 발견 기록에 남습니다. 정산·백업·복원에서도 발견 목록을 보존하고 중복 보상은 지급하지 않습니다. GPU occlusion 판정은 하지 않으므로 발견은 '화면에서 실제로 본 픽셀'이 아니라 '비행 중 가까이 접근한 로드 모델'입니다.

## 동작과 충돌

- 네이티브 키프레임을 Three.js Mixer로 재생하며 인스턴스별 위상을 렌더와 물리에 동일하게 적용합니다. 낮은 품질에서도 가까운 충돌 구조물은 움직이는 인스턴스로 유지합니다. 원거리 모델은 예산에 따라 정적 LOD가 될 수 있습니다.
- F16·L39·글라이더는 자동 클립 없이 실제 입력으로 조종면·기어가 작동합니다. 트랙터의 수동 `tractor_forward`는 차체 이동과 중복 재생하지 않습니다. 배너의 실제 morph animation은 가까운 native instance에서 유지합니다.
- 차량·선박의 전체 위치는 매 프레임 갱신하고, 네이티브 작동부도 같은 장면 시간을 사용합니다. 슬로 타임과 정지 시 장면 시계가 일치합니다.
- 삼각형과 박스가 함께 있는 125종에서 한쪽을 생략하지 않습니다. 타원체 비행체의 삼각형 face·edge·vertex sweep과 박스/OBB/BVH를 조합합니다. 미래의 회전 부품은 전체 보수 경계로 항로를 예약합니다. 회전하는 삼각형의 프레임 내 모든 중간 자세를 연속적으로 적분한 검사는 아닙니다.
- 새 아치의 필수 통과선은 실제 개구부 중앙으로 수정했습니다. `fortress_wall_gate`의 계단을 피하도록 실제 물리 개구부를 사용하고, 대각 보강재가 있는 `canyon_bridge`는 비행 통과 대신 상공 회피로 구성합니다.
- 분수·폭포·댐의 물·물안개와 굴뚝 연기는 원본 emitter 소켓에 맞춥니다. 입자는 물 384개·연기 192개의 고정 풀을 재사용합니다. 야간 등대는 실제 `fresnel_carriage`·`beacon` 노드에 맞춘 최대 3개의 광선·그림자 없는 광원을 사용합니다. 활주로 접근등 받침에 이 효과를 적용하지 않습니다.

원본 203개 리그와 775개 클립, 실제 시각과 물리 행렬 10,260개를 대조했습니다. 동적 모서리 3,034,008개가 전체 보수 경계 안에 들어감을 확인했습니다. 관련 검증의 최대 행렬 오차는 0이며, 경계 잔차는 부동소수점 수준입니다.

## UI와 격납고

HUD를 항공 계기형으로 다시 구성했습니다. 상단에는 테마 진행과 E·코인, 좌측에는 거리·속도·지면 고도, 우측에는 내구도·엔진·바람·발견 수를 배치합니다. 실제 HUD 값을 사용하고 화면 중앙의 경로는 비워 둡니다. 모바일 가로 화면과 모션 감소 규칙을 포함합니다.

모델 아카이브는 원본 이미지 403장, 11개 분류와 수량, 검색·동작 필터·페이지 이동·클립 목록·발견 스탬프를 제공합니다. 원본 렌더 JPEG를 '플레이 캡처'로 표시하지 않습니다. 테마 사전은 기존 실제 게임 렌더와 비행 사진 출처 구분을 유지합니다.

기체 선택은 22종으로 확장하고 기존 16종의 ID·순서·해금·강화 저장을 유지합니다. 지상 자세를 적용한 실제 최저 정점으로 격납고 바닥에 접지합니다. 대형 수송기와 글라이더까지 모바일 구도를 계산합니다. 360도 드래그·휠/핀치·뷰 버튼을 유지합니다.

비행 추적 카메라도 기체 폭·길이에 맞게 거리를 조정합니다. 22기체 × 6가지 급선회 자세의 132개 CPU 정점 투영에서 전 기체가 화면 안에 들어왔습니다. 최댓값은 화면 반폭·반높이의 약 85%이며 GPU 외관 검사는 아닙니다.

기존 승인 연출·보상·64퀘스트·20진로 미션·40업적·모든 설정을 유지합니다. 이름 승인 연출은 브라우저 로컬 프로필이며 외부 계정 승인이 아닙니다. 공개 연습 비행은 추가하지 않았습니다.

## 자원 관리

Hero/Gameplay/Distance LOD, 인스턴스 배치, 참조 수 기반 텍스처 공유·모델 캐시·지형 floating origin, 제한된 동시 다운로드와 실패 backoff를 사용합니다. 필요한 충돌 프록시만 읽고 지나간 구간의 참조를 해제합니다. 기체 카드 22장을 시작 시 한꺼번에 GPU 촬영하던 경로를 제거하고 원본 프리뷰와 선택 기체 촬영을 사용합니다. 캐시 revision을 4.0으로 갱신했습니다.

Balanced/High/Ultra는 DPR·그림자·AO·bloom·구름 수·지형 간격·모델 거리·배우·강수 예산을 실제로 변경합니다. PC High 60FPS·모바일 Balanced 30FPS는 실측 결과가 아닌 목표입니다.

사용하지 않는 compiled LOD의 재사용 대기 시간을 20초에서 5초로 줄인 뒤 동일한 CPU 30분 장면 검사에서 최대 compiled 항목 수가 98→63, 로드된 GLTF 수가 138→124로 감소했습니다. 데이터 보관 수의 변화이며 GPU 메모리나 FPS 개선율을 측정한 수치는 아닙니다.

## 검증 한계

CPU 정점 투영·SSR·Three.js 장면 준비는 실제 GPU 화면 검사가 아닙니다. 브라우저 GPU 외관·후처리·입력·멀티터치·PC/모바일 FPS·발열·실기기 메모리와 사람의 재미·생존 시간은 미측정입니다. 데이터 검사를 AAA 품질 인증으로 표현하지 않습니다.

이 환경에는 `$control-browser`가 없습니다. 적용한 Sites 지침은 “If `$control-browser` is unavailable, skip browser QA: do not start a preview server, install a browser, or improvise another browser-control path.”입니다. 따라서 브라우저나 우회 프리뷰 서버를 설치하지 않고 코드·데이터 검사와 공식 빌드·배포를 진행합니다.
