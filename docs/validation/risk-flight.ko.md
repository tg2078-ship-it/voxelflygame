# VOXEL AIRRUN 14.0 비행 규칙과 플레이테스트

## 무한 비행에서 달라진 선택

해안에서 가속한 뒤 작은 구조물을 스치면 점수를 얻고 열이 25%p 내려간다. 좁은 통로는 18%p, 정중앙 링 3연속은 28%p를 식힌다. 선도기의 비행운에 정렬하면 초당 10%p를 더 식힌다. 가속을 유지할 때 열은 초당 15.5%p 오른다. 중립에서는 초당 7.8%p, 감속할 때는 초당 16%p 내려간다. 100%에 이르면 경고음과 함께 엔진이 3초간 잠긴다.

키보드 C 또는 터치 회피 버튼으로 좌우 롤을 쓸 수 있다. 소형 장애물 판정을 0.35초 동안 피하고 4초 뒤 다시 쓴다. 실제 충돌 직전 0.15초 안에 롤을 시작하면 550점과 36%p 냉각을 받는다. 대형 구조물에는 방패가 먼저 소모된다. 치명적인 충돌 한 번은 내구도 1과 1.5초 보호 시간으로 버틸 수 있다. 보호가 끝난 뒤 또 치명상을 입으면 비행이 끝난다. 모션 감소를 켜면 롤 회전 및 순간 슬로모션을 줄이고 판정 시간은 유지한다.

격납고에서 선택하는 21대의 신규 기체를 같은 조명과 각도로 촬영했다. [기체별 모델 사진](flight-works.jpg)

## 장거리 속도와 판단 시간

1레벨 Skyhawk, 보통, 중립 스로틀의 순항 목표를 계산했다. 시간은 해당 속도로 166m를 비행하는 데 걸리는 값이다. 실제 통로 간격은 항로와 기체의 조종성에 따라 달라진다.

| 비행 거리 | 이전 속도 | 현재 속도 | 이전 166m | 현재 166m |
|---:|---:|---:|---:|---:|
| 0km | 166km/h | 166km/h | 3.61초 | 3.61초 |
| 10km | 333km/h | 290km/h | 1.79초 | 2.06초 |
| 30km | 435km/h | 314km/h | 1.37초 | 1.90초 |
| 60km | 544km/h | 321km/h | 1.10초 | 1.86초 |
| 100km | 668km/h | 323km/h | 0.89초 | 1.85초 |

이 기체의 순항 속도는 324km/h에 접근한다. 가속과 일시 효과를 겹친 목표 속도에도 약 460km/h의 상한이 있다. 기체·강화·난이도에 따른 속도 계수는 두 상한에 모두 적용된다.

## 점수와 코인

일반 점수 배율, 첫 콤보 기준이다. 가속 상태에서 장애물을 스치면 420점을 받는다. 현재 속도가 순항 목표의 112% 이상이면 근접·좁은 통로 점수에 80점이 더해진다.

| 행동 | 이전 기본 점수 | 현재 기본 점수 |
|---|---:|---:|
| 구조물 근접 통과 | 120 | 240 |
| 가속 중 근접 통과 | 120 | 420 |
| 좁은 통로 통과 | 300 | 390 |
| 완벽한 회피 롤 | 기능 없음 | 550 |
| 일반 링 | 150 | 150 |
| 링 정중앙 3연속 추가점 | 300 | 300 |
| 같은 테마에서 풍경 8종 발견 | 600 | 75 |

정산은 주운 코인에 거리 36m당 1코인과 보너스 115점당 1코인을 더한다. 이전 규칙은 거리 30m와 보너스 180점당 각각 1코인이었다. 두 항목은 각각 내림한다. 예를 들어 같은 3.6km에서 보너스가 0점에서 5,750점으로 오르면 정산은 50코인 늘어난다. 이전 규칙에서는 31코인이었다. 업데이트 이전에 저장한 결과는 당시 정산식으로 읽는다.

## 입력에서 재도전까지

1. 키보드·터치 입력을 60Hz 물리 단계에서 처리한다. 같은 단계에서 방향·기어·가속·회피 등 수동 명령을 묶어 기록한다. 열, 재사용 대기시간, 보호 시간과 점수 규칙은 tuning.ts에서 조정한다.
2. 시뮬레이션은 기체 궤적, 지면, 장애물 충돌 모델을 사용해 경고와 충돌을 판정한다. 렌더러가 아직 표시하지 못한 장애물은 충돌을 일으키지 않는다. 조종석은 엔진 열, 롤 준비 상태, 비상 복구를 구독한다.
3. 수동 비행이 추락 또는 완주로 끝나면 입력과 위치 표본을 저장한다. 같은 조건에서는 최고 점수 비행을 유지한다. 한 모드에서 다른 항로·기체 조건으로 비행을 끝내면 새 조건의 기록으로 교체한다. 입력 한도는 모드당 64KiB, 위치 표본은 최대 400개다. 입력 한도를 넘긴 비행은 일반 점수로 정산하고 완전한 기존 고스트를 보존한다.
4. 결과에서 R 또는 같은 항로 재도전을 누르면 같은 시드·난이도·기체·레벨로 출발한다. 같은 경로의 지형과 모델을 재사용하면서 통로의 가시성과 충돌 가능 상태를 다시 준비한다. 화면은 앞선 고스트와의 거리 차를 표시하고, 10m 이상 앞서면 반투명 기체를 서서히 보여준다.

## 확인한 범위

전체 게임 회귀 테스트 60개 묶음이 504초에 통과했다. 타입 검사, 구형 엔진 검사, 프레임워크 빌드와 GitHub Pages 정적 빌드가 성공했다. 전체 린트 결과는 오류 0개, 기존 경고 36개였다.

- 168개 패턴의 필수 통로 중앙을 통과시키는 검사에서 충돌은 0건이었다. 별도로 100개 시드에서 조작을 놓으면 98개 항로에서 45초 안에 치명 접촉이 있었고 95개 항로는 90초 안에 비행이 끝났다. 이전 검사에서 45초 이내의 종료를 세던 기준은 이번 비상 복구 규칙에 맞춰 첫 치명 접촉과 최종 추락을 각각 센다.
- 압축 입력 600프레임으로 기체 위치, 속도, 열, 내구도와 점수를 재현했다. 실제 장애물 모델을 읽은 별도 생성 항로에서는 563프레임의 입력을 재생해 이벤트 15개, 최종 충돌 좌표, 통계, 보상과 고스트 표본이 일치했다.
- 로컬 Chromium의 소프트웨어 WebGL에서 회피, 과열, 추락, 저장, R 재도전, 고스트 표시를 조작했다. 한 무한 비행에서 R 입력부터 비행 화면 전환까지 0.68초였다. 프레임 속도와 여러 기기에서의 재도전 지연은 실기 측정이 필요하다. 모델이 표시되는 시점까지 서로 다른 GPU에서 같은지 검증하지 않았다.
- 가로 844×390, 왼손 조작을 켠 터치 브라우저에서 54×54px 회피 버튼을 눌러 4초 재사용 대기 진입을 확인했다. 회피·가속·감속 버튼, 조이스틱과 열 표시 영역이 서로 겹치지 않았다. 실제 휴대폰의 입력 지연과 손가락 가림은 직접 확인이 필요하다.
- 이전 점수 600점을 전제한 탐색 검사, 과열 없는 무제한 가속을 전제한 검사, 첫 치명상·방패 관련 검사를 새 규칙에 맞게 바꿨다. 기존 프로필의 기록과 코인은 종전 규칙으로 검증한다.

## 직접 플레이할 항목

1. 무한 비행에서 Shift를 계속 누른 판과, 작은 구조물 옆을 스치며 가속한 판을 비교한다. 열을 식힐 경로를 보고 선택할 수 있는지 확인한다.
2. 같은 장애물에서 한 번은 일찍 C를 누르고 한 번은 직전에 누른다. 두 성공의 차이를 소리와 점수에서 구별할 수 있는지 본다.
3. 대형 구조물 앞에서 경고를 보고 피한다. 비상 복구를 썼다면 내구도 1이 된 이유와 다음 회피 방향이 읽히는지 본다.
4. 추락 후 R을 눌러 같은 통로를 다시 공략한다. 첫 시도의 고스트를 추월할 때 거리 표시와 기체를 구별할 수 있는지 본다.
5. 가로 휴대폰에서 왼손 조작으로 바꾸고, 조이스틱을 누른 채 회피·가속을 번갈아 쓴다. 손가락이 링과 경고를 가리는 위치를 확인한다.
6. 격납고에서 Skyhawk와 보유한 새 기체를 돌려 보고 출격한다. 실제 플레이에서 실루엣, 도장과 움직이는 조종면이 알아보기 쉬운지 본다.
