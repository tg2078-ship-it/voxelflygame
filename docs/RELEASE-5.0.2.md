# VOXEL AIRRUN 5.0.2 — 변경 사항과 검증

사용자가 제공한 `VOXEL-AIRRUN-5.0.1-GitHub-Max.zip`을 복원하고 2,437개 파일의 SHA-256을 확인한 뒤 수정했다. 원본 사본은 별도로 보존했다. 403종 모델과 원본 텍스처·충돌 자료를 삭제하거나 단순 모델로 대체하지 않았다. 원격 사이트를 게시한 상태는 아니며 이 문서는 로컬 수정본의 결과다.

## 바뀐 동작

| 영역 | 수정과 효과 |
|---|---|
| 로딩·입장 | 항공 정비 화면과 카드 스타일을 다듬고 실제 진행률을 접근성 속성과 연결했다. 호출명 오류를 설명하고 기본 PILOT 경로, 승인 연출 건너뛰기, 중복 제출 방지를 추가했다. |
| 격납고 | 정비·모델 로딩·오류 상태를 구별하고 출격 피드백과 선택 상태를 개선했다. 보이는 기체 목록에도 실제 게임 렌더 캡처를 순차 생성해, 선택하지 않은 카드가 계속 로딩으로 남던 문제를 수정했다. 한 번에 하나씩 촬영하며 비행에 들어가면 대기 작업을 취소한다. |
| 보상 | 확인 버튼의 강제 대기를 없애고 Escape·키보드 포커스·이전 포커스 복귀를 지원한다. 코인 확정과 장식 연출을 분리해 연출을 닫아도 보상은 유지한다. |
| 모델 표시 | 같은 재질이 여러 불연속 그룹에 쓰일 때 일부 삼각형을 버리던 병합 문제를 CPU·워커 경로 모두 수정했다. 인스턴싱이 숨긴 부모/미리보기 바닥 부품을 다시 보이게 하던 문제도 수정했다. |
| 다운로드 | 일시 실패 재시도는 최대 3회로 제한하고, 403/404/로그인 HTML 같은 영구 실패는 명시적 재시도 전까지 중단한다. 충돌 자료에도 같은 대기 규칙을 적용한다. |
| 그래픽 설정 | 실제 브라우저에서 재현한 HIGH→BALANCED 전환의 그림자 텍스처/샘플러 불일치를 수정했다. 그림자 상태가 바뀌면 장면·캐시 재질의 셰이더를 다시 준비한다. FPS/해상도만 바꾸는 경우 그림자 타깃을 불필요하게 재할당하지 않는다. |
| 해상도 | 1배 디스플레이·100% 설정에서도 적응형 해상도가 실제로 낮아질 수 있게 했다. 사용자가 지정한 최초 해상도는 유지한다. |
| 렌더 수명 | React가 재사용하는 캔버스를 정리할 때 강제로 WebGL 연결을 끊어 다음 초기화가 실패하던 문제를 수정했다. 유지되는 컨텍스트에서도 그림자 타깃을 명시적으로 해제한다. |
| 시점·입력 | E 연출의 카메라와 주시점에 같은 원점 보정을 적용했다. 포커스 상실·포인터 취소 후 격납고 드래그가 남지 않게 했다. 모바일 속도 입력의 중복·동시 입력과 모드 전환을 검사했다. |
| 파란 부스트 | 청록 코어·파란 쇼크 밴드·열 반응을 한 드로콜 안에서 표현한다. 연기/배기 발생과 위치를 시간 기준으로 보간해 30/60/144FPS 차이를 줄였다. 사용 횟수나 과열 대기 제한을 추가하지 않았다. |
| 날씨·구름 | 시간×현재 속도를 쓰던 비·눈·재 입자를 실제 진행 거리와 연결해 가속 시 입자가 튀지 않게 했다. 바람 방향과 구름의 물리적 덮임을 날씨에 연결하고 일출·노을 팔레트를 재사용한다. |
| 테마 | 화산 구간이 사막의 굴착기·태양광 설비 등을 그대로 가져오던 목록을 지질 모델 중심으로 수정했다. 원래 사막 자산은 사막에 유지한다. |
| 저장·정산 | IndexedDB 장애 뒤 더 최신 로컬 복구 저장을 무시하던 문제를 수정했다. 중복 정산이 새 비행의 체크포인트/화면을 지우지 않게 하고, 숨겨진 탭이나 미해결 렌더 오류에서 재개를 차단했다. |
| 미션 | 이전 환경에서 피격했다는 이유로 눈 속 무피격 미션이 영구 정지하던 문제를 수정했다. 가장 긴 연속 무피격 구간을 집계한다. |

## 기존 구현과 이번 수정의 구분

제공된 5.0.1에는 이미 바다와 분리된 콘크리트 격납고, 드래그 시점, 큰 기체 구도, 연습 비행 UI 제거, 미션 변경권 설명, 실제 렌더 기반 테마 사전, 좁은 비행 범위와 배경 풍경이 있었다. 이 기능들을 이번에 처음 만들었다고 주장하지 않는다. 기존 동작을 유지하면서 위 결함과 사용 경험을 보완했다.

`미션 변경권`은 미완료 미션을 같은 분류·등급의 다른 조건으로 바꾸는 권리다. 기존 설계는 500m 또는 30초 이상 유효 비행 정산당 1개, 최대 3개이며 변경 시 해당 미션 진행은 초기화된다. 유료 구매권을 추가하지 않았다.

사용자가 언급한 이미지 1~7 자체는 제공되지 않았다. 숨긴 미리보기 바닥이 노출될 수 있는 코드는 수정했지만, 이것이 그 이미지 속 모든 문양의 원인이라고 단정하지 않는다.

## 실행

Node.js 22.13 이상과 pnpm 11.25.0을 사용한다. 프로젝트 루트에서 실행한다.

```sh
npx --yes pnpm@11.25.0 install --frozen-lockfile
npm run dev
```

검사와 배포용 빌드:

```sh
npm run typecheck
npm run lint:game
npm run test:game
npm run build
```

로컬 실행은 원본 LOD0을 유지한다. 기존 배포 빌드의 256MiB 모델 전달 프로필은 모든 기체·동작·충돌 자료와 원거리 LOD를 보존하면서 일부 환경의 근거리 단계를 LOD1으로 선택한다. 원본 `public/models`는 변경하지 않는다. 이 자산 전달 정책은 5.0.1부터 있던 정책이다.

## 확인한 범위

- 기존 게임 회귀 검사 29개 묶음 통과. 30분 분량 스트리밍은 시뮬레이션 검사이며 실제 30분 GPU 플레이와 구분한다.
- 새 자산 안정성 검사 39개, 비행 효과 검사 224개, 적응형 해상도 12가지와 E 카메라 원점 8가지 회귀 검사 통과.
- 품질 전환 회귀를 포함한 화면 경계 검사 2,518개, 핵심 규칙/터치 입력 검사 2,620개, UI 계약 검사 20개 통과.
- TypeScript 검사, 게임 ESLint 검사, 배포 빌드 통과.
- 실제 Chromium에서 등록·승인·격납고·드래그·출격·가속·일시정지를 조작했다. 소프트웨어 GPU에서 품질을 HIGH↔BALANCED로 바꿀 때 발생하던 WebGL 오류를 재현해 수정하고, 재검사에서 관련 오류 0건을 확인했다.
- 브라우저 기능 검사와 별도로 1440×900, 390×844, 844×390에서 로딩·카드·보상 UI 레이아웃을 확인했다.

실제 PC/모바일 하드웨어의 60/30FPS·발열·장시간 플레이와 사람 대상 재미 평가는 수행하지 않았다. 자동 검사나 소프트웨어 GPU 캡처를 그 결과로 확대하지 않는다. 모든 오류가 없다는 보장이나 외부 사이트 배포 완료를 뜻하지 않는다.
